# Feature Specification: Unified Agent Generators

**Feature Branch**: `062-unified-agent-generators`
**Created**: 2026-04-10
**Status**: Draft
**Input**: User description: "Migrar todos os generators e chamadas OpenAI diretas para usar o Managed Agent via Sessions API"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - Internal Programmatic Agent Client (Priority: P1)

The system needs an internal way for server-side code (generators, background jobs, scheduled tasks) to interact with the Managed Agent programmatically — not just through the chat UI. This client creates a session, sends a prompt, waits for the complete response, and returns the result. It handles auto-provisioning if the team doesn't have an Agent yet.

**Why this priority**: This is the foundational infrastructure that enables all other stories. Without a programmatic client, generators cannot communicate with the Agent.

**Independent Test**: Call the internal client from a server-side function with a prompt and a team ID. Verify it creates a session, communicates with the Agent, and returns the response text.

**Acceptance Scenarios**:

1. **Given** a valid team with a provisioned Agent, **When** the internal client is called with a prompt, **Then** it returns the Agent's complete response
2. **Given** a team without a provisioned Agent, **When** the internal client is called, **Then** it auto-provisions the Agent before proceeding
3. **Given** a prompt that requires MCP tool usage, **When** the internal client processes it, **Then** the Agent calls the tools and incorporates results into its response

---

### User Story 2 - Brand DNA Analysis Uses Agent Context (Priority: P1)

When a new store goes through onboarding, the brand DNA analysis should leverage the Managed Agent — which already has the store's product catalog, segment, and visual analysis loaded — instead of making a raw, context-free call to an external model. The result is a richer, more accurate brand DNA because the Agent understands the full picture of the business.

**Why this priority**: Brand DNA is the foundational data that shapes all subsequent content generation (campaigns, copies, assets). If this analysis is shallow due to lack of context, everything downstream suffers.

**Independent Test**: Trigger brand DNA analysis for a store with products and visual data. Verify the output references specific products, store segment, and visual palette — information only available through the Agent's context.

**Acceptance Scenarios**:

1. **Given** a store with products and visual data, **When** brand DNA analysis runs, **Then** the analysis incorporates store-specific context (product names, segment, visual style) rather than generic guesses
2. **Given** the Agent is provisioned for the team, **When** brand DNA analysis is triggered, **Then** the system reuses the existing Agent rather than making a standalone model call
3. **Given** the Agent is unavailable or not yet provisioned, **When** brand DNA analysis is triggered, **Then** the system falls back gracefully with an appropriate error message

---

### User Story 3 - Campaign Content Generation Through Agent (Priority: P1)

When a user generates seasonal campaign content (copies, email templates, video scripts, asset designs), the generation should go through the Managed Agent. The Agent already knows the brand's tone of voice, target audience, product catalog, and positioning — producing content that is on-brand without requiring the generator to re-fetch and re-inject all that context manually.

**Why this priority**: Campaign generation is the most-used feature and produces customer-facing content. Using the Agent's full context directly improves content quality and brand consistency.

**Independent Test**: Generate a seasonal campaign for a store with brand DNA configured. Verify the output uses the brand's tone of voice, mentions real products, and follows the brand positioning — without those details being passed explicitly in the generation call.

**Acceptance Scenarios**:

1. **Given** a store with brand DNA and products, **When** a seasonal campaign is generated, **Then** the content reflects the brand's tone, audience, and positioning
2. **Given** a campaign generation request, **When** the Agent processes it, **Then** all deliverable types (copies, emails, assets, video scripts) are generated with brand-consistent context
3. **Given** a campaign for a specific seasonal date, **When** the Agent generates content, **Then** the content references relevant products from the store's actual catalog

---

### User Story 4 - Follow-up Suggestions via Agent (Priority: P2)

After the Agent responds in chat, follow-up suggestions should be generated by the Agent itself rather than by a separate model call. The Agent knows the conversation history and context, so it can produce more relevant follow-up questions.

**Why this priority**: Follow-ups are visible to users after every response. Using the Agent ensures suggestions are contextually relevant to the ongoing conversation rather than generic.

**Independent Test**: Send a message in chat and verify the follow-up suggestions reference the conversation topic and the user's store context, not generic questions.

**Acceptance Scenarios**:

1. **Given** a completed Agent response, **When** follow-up suggestions are generated, **Then** suggestions are contextually relevant to the conversation and the user's business
2. **Given** the Agent has conversation history, **When** follow-ups are generated, **Then** they build on what was discussed rather than repeating or being generic

---

### User Story 5 - Workflow AI Steps Dual-Mode Support (Priority: P3)

Workflow AI steps need evaluation: some workflows may benefit from Agent context (e.g., marketing automation workflows), while others are generic data transformations that don't need brand context. The system should support both paths — Agent-based for brand-aware tasks, and direct for simple transformations.

**Why this priority**: Workflows are an independent automation system. Forcing all AI steps through the Agent may add latency and unnecessary context for simple transformations. This requires careful scoping.

**Independent Test**: Run a workflow with an AI step and verify it produces the expected output. The mode selection (agent vs direct) is transparent to the user for now.

**Acceptance Scenarios**:

1. **Given** a workflow AI step that benefits from brand context (e.g., "generate marketing email"), **When** executed, **Then** the step uses the Agent and produces brand-aware content
2. **Given** a workflow AI step for generic transformation (e.g., "summarize this text"), **When** executed, **Then** the step uses a direct model call without Agent overhead

---

### Edge Cases

- What happens when the Agent is being provisioned by another request simultaneously? The system must handle concurrent provisioning gracefully (idempotent check).
- How does the system handle Agent session timeouts during long-running generation tasks? Retry with a new session.
- What happens if the Agent's MCP server is temporarily unavailable during a generation request? Return an error with a clear message, do not fail silently.
- How does the system extract structured output (JSON) from the Agent's natural language response? Use explicit instructions in the prompt and parse the response.
- What happens when the Agent's response doesn't match the expected format? Retry once with a more explicit prompt, then fail with a clear error.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: System MUST provide an internal programmatic client for server-side code to communicate with the Managed Agent
- **FR-002**: The programmatic client MUST create sessions, send messages, and return complete responses
- **FR-003**: The programmatic client MUST auto-provision the Agent if the team doesn't have one yet
- **FR-004**: Brand DNA analysis MUST use the Managed Agent instead of standalone model calls
- **FR-005**: Seasonal campaign generation (concepts, copies, emails, assets, video scripts) MUST use the Managed Agent
- **FR-006**: Follow-up suggestion generation MUST use the Managed Agent's conversation context
- **FR-007**: The system MUST support structured output extraction from Agent responses (for generators that need specific data formats like JSON)
- **FR-008**: Store visual analysis MUST use the Managed Agent
- **FR-009**: Asset generation MUST use the Managed Agent
- **FR-010**: Email template generation MUST use the Managed Agent
- **FR-011**: Workflow AI steps MUST continue to function, with the default provider migrated from the external model to the platform's own AI provider
- **FR-012**: The system MUST gracefully handle Agent unavailability with appropriate error messages
- **FR-013**: After migration, the system MUST NOT require any external model provider API keys (e.g., OpenAI) for core features — only the platform's own AI provider key
- **FR-014**: The external model provider SDK packages MUST be removed from project dependencies after migration

### Key Entities

- **Programmatic Agent Client**: Internal service that creates sessions and communicates with the Managed Agent from server-side code, handling provisioning, message sending, and response extraction
- **Generator**: A server-side function that produces structured content (brand DNA, campaigns, emails, assets) — currently calling external models directly, to be migrated to use the Agent
- **Structured Response**: A formatted output from the Agent that follows a specific schema (JSON), extracted from the Agent's response via parsing or explicit instruction

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 100% of content generation features (brand DNA, campaigns, emails, assets, visual analysis) operate through the Managed Agent with zero direct external model calls
- **SC-002**: Generated content quality improves — brand DNA analysis references at least 3 store-specific details (products, segment, visual style) that were previously absent in context-free generation
- **SC-003**: Campaign content matches the brand's configured tone of voice in at least 90% of generations, as validated by comparing output against brand DNA attributes
- **SC-004**: Follow-up suggestions are contextually relevant to the conversation topic in at least 80% of cases
- **SC-005**: The external model provider dependency is fully removed from core features — the system operates with a single AI provider
- **SC-006**: Generator response times remain within 2x of current times (acceptable overhead for added context quality)
- **SC-007**: Workflow AI steps continue to function with the same success rate as before migration

## Assumptions

- The Managed Agent's system prompt already contains brand DNA, store context, and skill information (confirmed — `buildOrchestratorSystemPrompt` handles this)
- The Agent can handle structured output requests via careful prompting (e.g., "respond only with valid JSON matching this schema")
- Agent provisioning is idempotent and handles concurrent requests safely
- The MCP server tools provide the same data access the generators previously had (store products, sales, etc.)
- Workflow AI steps that need direct model access will use the platform's own AI provider directly rather than external providers

## Scope Boundaries

**In scope**:

- Internal programmatic Agent client
- Migration of 6 generators (brand-dna, seasonal-campaign, asset, email-template, store-visual, follow-ups)
- Removal of external model provider packages from dependencies
- Removal of `getOpenAIProvider` and related provider code
- Workflow AI step evaluation and provider migration

**Out of scope**:

- Changes to the chat UI or streaming behavior
- Changes to the MCP server or its tools
- Telegram processor migration (legacy system, separate effort)
- Billing changes for Agent usage

# Implementation Plan: App Event Triggers

**Branch**: `021-app-event-triggers` | **Date**: 2026-02-15 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/021-app-event-triggers/spec.md`

## Summary

Enable external apps (GitHub, Discord, Slack, etc.) to trigger workflow execution via Composio trigger subscriptions. When an event fires in a connected app (e.g., PR opened), Composio sends a webhook callback to our endpoint, which routes the event to the linked workflow and executes a multi-step pipeline with step-by-step tracking. Includes a new `claude_agent` action type for AI-powered analysis steps within pipelines.

## Technical Context

**Language/Version**: TypeScript 5 (strict mode) + Next.js 16.1.6 (App Router), React 19
**Primary Dependencies**: `composio-core` ^0.6.3 (triggers API), `@ai-sdk/openai` (Claude agent steps), `@supabase/ssr` + `@supabase/supabase-js` (Realtime for progress), TanStack React Query
**Storage**: Supabase PostgreSQL — new `trigger_subscriptions` table, extended `agent_workflows` and `agent_workflow_runs`
**Testing**: Vitest + @testing-library/react (unit), Playwright (e2e)
**Target Platform**: Web (Vercel deployment)
**Project Type**: Web application (Next.js App Router)
**Performance Goals**: Event-to-first-step < 30 seconds (SC-001), real-time updates < 2 seconds (SC-003), 100 concurrent runs (SC-006)
**Constraints**: Composio allows ONE webhook URL per account (all events to single endpoint), at-least-once delivery (need idempotency)
**Scale/Scope**: 50 active trigger subscriptions per workspace (configurable limit), 5+ steps per pipeline

## Architecture Overview

### Event Flow

```
External App (GitHub/Discord/Slack)
        │
        ▼
   Composio Cloud
   (trigger subscription monitors app)
        │
        ▼ POST webhook callback
   /api/composio/webhook (route.ts)
        │
        ├─ Validate payload (Zod)
        ├─ Lookup trigger_subscriptions by trigger metadata
        ├─ Check idempotency (event_log_id)
        ├─ Apply event filters
        │
        ▼
   pipeline-executor.ts
        │
        ├─ Create agent_workflow_runs record
        ├─ For each action (sequential):
        │   ├─ composio_action → Composio tools.execute()
        │   ├─ ai_transform → AI SDK (simple transform)
        │   ├─ claude_agent → AI SDK + tools (analysis)
        │   └─ notify → Internal/Slack/Email
        ├─ Update pipeline_steps after each step
        │
        ▼
   Supabase Realtime → Client UI (step progress)
```

### Key Design Decisions

1. **Single Composio webhook endpoint**: Composio sends ALL trigger events to one URL. We route internally based on trigger metadata + `trigger_subscriptions` table lookup.

2. **Extend agent_workflows system**: The `agent_workflows` table (skills system) is the primary workflow system users interact with via chat. We extend it with trigger subscriptions rather than using the separate `workflows` editor tables.

3. **Pipeline step tracking in JSONB**: Step execution records stored as JSONB array in `agent_workflow_runs.pipeline_steps`. This avoids a new join table and keeps the run record self-contained.

4. **Idempotency via `event_log_id`**: Composio provides a unique `log_id` per event. We store it and check before creating runs to prevent duplicates.

5. **Claude agent step reuses AI SDK**: The `claude_agent` action type uses the same `@ai-sdk/openai` infrastructure as existing `ai_transform` but with tool-calling capabilities and structured output.

6. **LLM tool updates**: `SNEW_CREATE_WORKFLOW` extended to accept `app_event` trigger type. When the agent creates a workflow with an app event trigger, it automatically creates the Composio subscription.
